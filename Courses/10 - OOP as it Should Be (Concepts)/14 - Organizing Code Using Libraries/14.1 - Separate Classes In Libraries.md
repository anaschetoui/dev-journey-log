# Separate Classes In Libraries

## 📝 مقدمة

عندما يكبر المشروع، من الأفضل ألا تكون جميع الفئات مكتوبة في ملف واحد. يتم وضع كل `class` في ملف Header مستقل داخل المشروع، ثم يتم استخدام `#include` لإضافة الفئات المطلوبة إلى الملفات التي تحتاج إليها.

هذا يجعل ملف `main` أبسط، ويساعد على تنظيم الكود والتحكم فيه بشكل أفضل.

---

## 🧠 مراجعة سريعة

كان الكود الأصلي يحتوي على فئتين مكتوبتين في الملف نفسه:

- `clsPerson`
- `clsEmployee` التي ترث من `clsPerson`

بعد الفصل، أصبحت كل فئة في ملف Header مستقل:

- `clsPerson.h`
- `clsEmployee.h`

ويحتوي `main` على الكود المطلوب لاستخدام هذه الفئات.

---

## 🎯 تعريف: Header File

> **Header File**
>
> ملف يوضع فيه تعريف `class` ويمكن تضمينه في الملفات التي تحتاج إلى استخدام هذه الفئة.

في هذا الأسلوب، توضع كل فئة في ملف Header خاص بها، مثل `clsPerson.h` و`clsEmployee.h`.

---

## ⚙️ فصل `clsPerson` في ملف Header مستقل

تم نقل الكود الكامل للفئة `clsPerson` إلى ملف باسم `clsPerson.h`.

يحتوي الملف على `#include <iostream>`، ثم `using namespace std;`، ثم تعريف `clsPerson`.

<div dir="ltr" style="text-align:left;font-family:'Arial',sans-serif;">

```cpp
#pragma once

#include <iostream>
using namespace std;

class clsPerson
{
    // ...
};
```
</div>

---

## ⚙️ فصل `clsEmployee` في ملف Header مستقل

تم أيضًا نقل الكود الكامل للفئة `clsEmployee` إلى ملف باسم `clsEmployee.h`.

لأن `clsEmployee` ترث من `clsPerson`:

<div dir="ltr" style="text-align:left;font-family:'Arial',sans-serif;">

```cpp
class clsEmployee : public clsPerson
```
</div>

فإن `clsEmployee.h` تحتاج إلى تضمين `clsPerson.h`:

<div dir="ltr" style="text-align:left;font-family:'Arial',sans-serif;">

```cpp
#pragma once

#include <iostream>
#include "clsPerson.h"

using namespace std;

class clsEmployee : public clsPerson
{
    // ...
};
```
</div>

أي أن الملف الذي يحتوي على فئة تعتمد على فئة أخرى يضمّن Header الخاصة بالفئة الأخرى.

---

## 💻 مثال: `main` بعد الفصل

بعد نقل الفئات إلى ملفاتها، يحتوي `main` على الكود الأساسي المستخدم لإنشاء الكائن واستدعاء `Print()`:

<div dir="ltr" style="text-align:left;font-family:'Arial',sans-serif;">

```cpp
#include <iostream>
#include "clsPerson.h";
#include "clsEmployee.h";

using namespace std;

int main()
{
    clsEmployee Employee1(10, "Mohammed", "Abu-Hadhoud",
        "A@a.com", "8298982", "CEO", "ProgrammingAdvices", 5000);

    Employee1.Print();

    system("pause>0");
    return 0;
}
```
</div>

أصبح `main` أبسط، لأن تعريفات `clsPerson` و`clsEmployee` لم تعد مكتوبة داخله.

---

## ⚙️ استخدام `#include`

يتم استخدام `#include` لإضافة Header File إلى الملف الحالي.

في `main`:

<div dir="ltr" style="text-align:left;font-family:'Arial',sans-serif;">

```cpp
#include "clsPerson.h"
#include "clsEmployee.h"
```
</div>

وفي `clsEmployee.h`:

<div dir="ltr" style="text-align:left;font-family:'Arial',sans-serif;">

```cpp
#include "clsPerson.h"
```
</div>

عند تضمين Header File من داخل المشروع، يتم استخدام علامات الاقتباس المزدوجة، مثل `#include "clsPerson.h"`.

---

## ⚠️ مشكلة تكرار تعريف `clsPerson`

في حالة تضمين `clsPerson.h` مباشرةً في `main`، وتضمين `clsEmployee.h` في `main`، بينما تقوم `clsEmployee.h` أيضًا بتضمين `clsPerson.h`، يمكن أن يتم تعريف `clsPerson` أكثر من مرة.

يظهر عندها خطأ مثل:

<div dir="ltr" style="text-align:left;font-family:'Arial',sans-serif;">

```text
class clsPerson: class type redefinition
```
</div>

سبب المشكلة هو وصول تعريف `clsPerson` إلى المترجم أكثر من مرة.

---

## ⚙️ الحل: `#pragma once`

يوضع الأمر التالي في بداية كل Header File:

<div dir="ltr" style="text-align:left;font-family:'Arial',sans-serif;">

```cpp
#pragma once
```
</div>

يوجد `#pragma once` في بداية `clsPerson.h`، وكذلك في بداية `clsEmployee.h`.

وظيفته أن يجعل محتوى Header File يُضمّن مرة واحدة فقط حتى عند محاولة تضمينه أكثر من مرة.

---

## 📌 قاعدة مهمة عند استخدام Header Files

عند فصل الفئات في ملفات مستقلة:

1. ضع كل `class` في Header File مستقلة.
2. ضع `#pragma once` في بداية كل Header File.
3. ضمّن الفئات التي تعتمد عليها باستخدام `#include`.
4. استخدم `#include "FileName.h"` مع ملفات المشروع.
5. اجعل `main` يركّز على استخدام الفئات بدل تعريفها كلها داخله.

---



## ⚠️ ملاحظات

- `clsPerson.h` يحتوي على تعريف `clsPerson` كاملًا، مع أعضائها ودوالها.
- `clsEmployee.h` يحتوي على `#include "clsPerson.h"` لأن `clsEmployee` تعتمد على `clsPerson` من خلال الوراثة.
- `main` يضمّن `clsPerson.h` و`clsEmployee.h` ثم ينشئ `Employee1` من الفئة `clsEmployee`.
- عندما يتم تضمين `clsPerson.h` بشكل مباشر وغير مباشر، يمكن أن يحدث تكرار في تعريف `clsPerson`.
- `#pragma once` موجود في بداية ملفات Header لمنع هذا التضمين المتكرر.

---

## 💡 الفكرة الأساسية

فصل كل `class` في Header File مستقلة يجعل الكود أكثر تنظيمًا، ويجعل `main` أبسط. وإذا كانت فئة تعتمد على فئة أخرى، يتم تضمين Header الخاصة بها باستخدام `#include`.

أما `#pragma once` فتمنع تضمين ملف Header أكثر من مرة.

---

## 🔑 ملخص

- كل `class` يمكن وضعها في Header File مستقلة.
- `clsEmployee.h` يضمّن `clsPerson.h` لأن `clsEmployee` ترث من `clsPerson`.
- `main` يضمّن الملفات المطلوبة ويستخدم الفئات.
- `#pragma once` تمنع تكرار تعريف الفئة عند تضمين Header أكثر من مرة.
- هذا التنظيم يجعل الكود في `main` أنظف وأسهل في التعامل معه.

## 📝 Introduction

When a project becomes bigger, it is better not to write all classes in one file. Each `class` can be placed in a separate Header File, then `#include` can be used to add the classes needed by other files.

This makes `main` simpler and helps organize and control the code.

---

## 🧠 Quick Recap

The original code had two classes in the same file:

- `clsPerson`
- `clsEmployee`, which inherits from `clsPerson`

After separation, each class was placed in its own Header File:

- `clsPerson.h`
- `clsEmployee.h`

The `main` file contains the code needed to use these classes.

---

## 🎯 Definition: Header File

> **Header File**
>
> A file where a `class` definition is placed and which can be included in files that need to use that class.

In this style, each class has its own Header File, such as `clsPerson.h` and `clsEmployee.h`.

---

## ⚙️ Separating `clsPerson` into Its Own Header File

The full `clsPerson` code is moved to a file named `clsPerson.h`.

The file contains `#include <iostream>`, then `using namespace std;`, and then the `clsPerson` definition.

```cpp
#pragma once

#include <iostream>
using namespace std;

class clsPerson
{
    // ...
};
```

---

## ⚙️ Separating `clsEmployee` into Its Own Header File

The full `clsEmployee` code is also moved to a file named `clsEmployee.h`.

`clsEmployee` inherits from `clsPerson`:

```cpp
class clsEmployee : public clsPerson
```

So `clsEmployee.h` needs to include `clsPerson.h`:

```cpp
#pragma once

#include <iostream>
#include "clsPerson.h"

using namespace std;

class clsEmployee : public clsPerson
{
    // ...
};
```

A file that contains a class depending on another class includes the other class's Header File.

---

## 💻 Example: `main` After Separation

After moving the classes to their own files, `main` contains the main code used to create the object and call `Print()`:

```cpp
#include <iostream>
#include "clsPerson.h";
#include "clsEmployee.h";

using namespace std;

int main()
{
    clsEmployee Employee1(10, "Mohammed", "Abu-Hadhoud",
        "A@a.com", "8298982", "CEO", "ProgrammingAdvices", 5000);

    Employee1.Print();

    system("pause>0");
    return 0;
}
```

`main` is now simpler because the definitions of `clsPerson` and `clsEmployee` are no longer written inside it.

---

## ⚙️ Using `#include`

`#include` is used to add a Header File to the current file.

In `main`:

```cpp
#include "clsPerson.h"
#include "clsEmployee.h"
```

And in `clsEmployee.h`:

```cpp
#include "clsPerson.h"
```

When including a Header File from the project, double quotation marks are used, such as `#include "clsPerson.h"`.

---

## ⚠️ The Problem of Defining `clsPerson` More Than Once

If `main` includes `clsPerson.h` directly, includes `clsEmployee.h`, and `clsEmployee.h` also includes `clsPerson.h`, the definition of `clsPerson` can be included more than once.

This can cause an error such as:

```text
class clsPerson: class type redefinition
```

The problem is that the definition of `clsPerson` reaches the compiler more than once.

---

## ⚙️ The Solution: `#pragma once`

The following is placed at the beginning of every Header File:

```cpp
#pragma once
```

`#pragma once` is placed at the beginning of both `clsPerson.h` and `clsEmployee.h`.

Its purpose is to make the Header File content included only once, even when the file is included more than one time.

---

## 📌 Important Rule for Header Files

When separating classes into independent files:

1. Put each `class` in its own Header File.
2. Put `#pragma once` at the beginning of every Header File.
3. Include classes that the file depends on with `#include`.
4. Use `#include "FileName.h"` with project files.
5. Keep `main` focused on using classes instead of defining all of them inside it.

---

## ⚠️ Notes

- `clsPerson.h` contains the full definition of `clsPerson`, including its members and functions.
- `clsEmployee.h` contains `#include "clsPerson.h"` because `clsEmployee` depends on `clsPerson` through inheritance.
- `main` includes `clsPerson.h` and `clsEmployee.h`, then creates `Employee1` from `clsEmployee`.
- When `clsPerson.h` is included directly and indirectly, the definition of `clsPerson` can be repeated.
- `#pragma once` is placed at the beginning of Header Files to prevent this repeated inclusion.

---

## 💡 Key Idea

Putting each `class` in its own Header File makes the code more organized and keeps `main` simpler. When one class depends on another class, include the other class's Header File with `#include`.

`#pragma once` prevents the Header File from being included more than once.

---

## 🔑 Summary

- Each `class` can be placed in its own Header File.
- `clsEmployee.h` includes `clsPerson.h` because `clsEmployee` inherits from `clsPerson`.
- `main` includes the required files and uses the classes.
- `#pragma once` prevents repeated class definitions when a Header File is included more than once.
- This organization keeps the code in `main` cleaner and easier to manage.
