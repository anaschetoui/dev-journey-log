# Function Overriding

---

## 📝 مقدمة

بعد استخدام `Inheritance`، يمكن أن ترث `Derived Class` الدوال الموجودة في `Base Class`.

لكن أحيانًا تكون الدالة الموروثة غير مناسبة للـ `Derived Class`. في هذه الحالة، يمكن تعريف دالة جديدة في الـ `Derived Class` بنفس الاسم ونفس الـ signature، بحيث تُستخدم الدالة الجديدة عند استدعائها من خلال كائن الـ `Derived Class`.

---

## 🧠 مراجعة سريعة

`clsEmployee` ترث من `clsPerson`.

لذلك ورثت `Employee` دالة `Print()` الموجودة في `Person`.

لكن `Print()` الخاصة بـ `Person` تطبع بيانات `Person` فقط، بينما `Employee` لديها بيانات إضافية مثل `Title` و`Department` و`Salary`.

---

## 🎯 تعريف: Function Overriding

> **Function Overriding**
>
> إعادة تعريف دالة موروثة داخل الـ `Derived Class` باستخدام نفس الاسم ونفس الـ signature، بحيث يتم استخدام الدالة الجديدة عند استدعائها من خلال الـ `Derived Class`.

---

## ⚙️ كيف تعمل Function Overriding؟

إذا كانت `Base Class` تحتوي على:

`()void Print`

ثم عرّفنا داخل `Derived Class`:

`()void Print`

بنفس الاسم ونفس الـ signature، فإن نسخة `Derived Class` تُستخدم عند استدعاء الدالة من خلال كائن الـ `Derived Class`.

في المثال، `()Employee1.Print` تستدعي `()Print` الموجودة داخل `clsEmployee` بدل `()Print` الموجودة داخل `clsPerson`.

---

## 💻 مثال: Overriding لـ `Print()`

    string _Title;

    clsEmployee(int ID, string FirstName, string LastName, string Email, string Phone,string Title,string Department, float Salary)

في المثال، توجد `()Print` في `clsPerson` وتوجد `()Print` أخرى في `clsEmployee`.

الدالتان لهما نفس الاسم ونفس الـ signature.

لذلك عند كتابة:

`()Employee1.Print;`

يتم استخدام `()Print` الموجودة في `clsEmployee`.

هذه النسخة تطبع بيانات `Person` وتضيف:

- `Title`
- `Department`
- `Salary`

---

## 📌 لماذا نحتاج Overriding؟

الدالة الموروثة `()Print` في `Person` لا تحتوي على كود لطباعة بيانات `Employee` الجديدة.

لذلك لا تكفي لـ `Employee`.

باستخدام `Overriding`، نعرّف `()Print` من جديد داخل `Employee` ونكتب فيها ما يناسب بيانات `Employee`.

---

## ⚙️ نفس الاسم ونفس الـ Signature

لكي نستخدم `Overriding` بالطريقة الموجودة هنا، يجب أن يكون اسم الدالة نفسه وأن تكون الـ signature نفسها.

في الـ `Base Class`:

`()void Print`

وفي الـ `Derived Class`:

`()void Print`

عند تطابقهما، تُستخدم نسخة `Derived Class` عند استدعاء الدالة من خلال `Employee1`.

---

## 📌 الوصول إلى الدالة الأصلية

يمكن أن نحتاج إلى استدعاء الدالة الموجودة في `Base Class` نفسها.

من داخل الـ `Derived Class` نستخدم اسم الـ `Base Class` مع `::` ثم اسم الدالة:

`()clsPerson::Print`

بهذه الطريقة نصل إلى `()Print` الأصلية الموجودة في `clsPerson`.

---

## 📌 الوصول إلى بيانات الـ Base Class

المتغيّرات:

`_ID` و`_FirstName` و`_LastName` و`_Email` و`_Phone`

موجودة في `clsPerson` وهي `private`.

لذلك لا يتم الوصول إليها مباشرة من `clsEmployee`.

بدلًا من ذلك، يتم الوصول إلى القيم من خلال الدوال المتاحة في `Person`، مثل:

- `()ID`
- `()FirstName`
- `()LastName`
- `()Email`
- `()Phone`
- `()FullName`

وهذا هو الأسلوب المستخدم داخل `()Print` الجديدة.

---

## 📌 الفرق بين `()Print` في `Person` و`Employee`

دالة `()Print` في `Person` تطبع:

`ID` و`FirstName` و`LastName` و`FullName` و`Email` و`Phone`.

أما `()Print` في `Employee` فتطبع هذه البيانات أيضًا، ثم تضيف:

`Title` و`Department` و`Salary`.

لذلك أصبحت `()Print` في `Employee` مناسبة للبيانات الخاصة بـ `Employee`.

---

## 📚 المصطلحات

| المصطلح | المعنى |
|---|---|
| Function Overriding | إعادة تعريف دالة موروثة بنفس الاسم ونفس الـ signature |
| Signature | اسم الدالة وParameters |
| Base Class | الكلاس التي تحتوي على الدالة الأصلية |
| Derived Class | الكلاس التي تعيد تعريف الدالة الموروثة |
| `()BaseClass::FunctionName` | صيغة الوصول إلى الدالة الموجودة في الـ `Base Class` |

---

## ⚠️ ملاحظات

- يجب استخدام نفس اسم الدالة ونفس الـ signature لعمل `Overriding` بالطريقة المستخدمة هنا.
- `()Employee1.Print` تستدعي `()Print` الموجودة في `clsEmployee`.
- `()Print` الموجودة في `clsPerson` تبقى موجودة ويمكن الوصول إليها باستخدام `()clsPerson::Print`.
- لا يمكن الوصول مباشرة إلى المتغيّرات `private` الخاصة بـ `clsPerson` من `clsEmployee`.
- يتم الوصول إلى هذه البيانات من خلال الدوال المتاحة، مثل `()ID` و`()FirstName` و`()Email`.
- `()Print` الجديدة في `Employee` تطبع أيضًا `Title` و`Department` و`Salary`.

---

## 💡 الفكرة الأساسية

`Inheritance` جعلت `Employee` ترث `()Print` من `Person`.

لكن لأن `()Print` الأصلية لا تناسب بيانات `Employee`، نعرّف `()Print` جديدة في `Employee` بنفس الاسم ونفس الـ signature.

وهذا هو `Function Overriding`.

---

## 🔑 ملخص

- `Function Overriding` تعني إعادة تعريف دالة موروثة داخل `Derived Class`.
- يجب أن يكون الاسم والـ signature متطابقين في المثال.
- `()Employee1.Print` تستخدم `()Print` الموجودة في `Employee`.
- يمكن الوصول إلى `()Print` الأصلية باستخدام:
  `()clsPerson::Print`
- بيانات `Person` الخاصة لا يتم الوصول إليها مباشرة لأنها `private`.
- يتم الوصول إليها من خلال الدوال المتاحة مثل `()ID` و`()FirstName` و`()Email`.
- `Employee` تستطيع إضافة منطقها الخاص إلى `()Print` الجديدة.

## 📝 Introduction

After using `Inheritance`, a `Derived Class` can inherit functions from a `Base Class`.

Sometimes the inherited function is not suitable for the `Derived Class`. In that case, we can define a new function in the `Derived Class` with the same name and the same signature. The new function is then used when it is called through an object of the `Derived Class`.

---

## 🧠 Quick Recap

`clsEmployee` inherits from `clsPerson`.

So `Employee` also inherits the `Print()` function from `Person`.

But the `Print()` in `Person` prints only `Person` data, while `Employee` has extra data such as `Title`, `Department`, and `Salary`.

---

## 🎯 Definition: Function Overriding

> **Function Overriding**
>
> Defining a new version of an inherited function inside the `Derived Class` using the same function name and the same signature, so the new function is used when it is called through the `Derived Class`.

---

## ⚙️ How Function Overriding Works

Suppose the `Base Class` has:

`void Print()`

Then we define another function inside the `Derived Class`:

`void Print()`

with the same name and the same signature.

The new function becomes the version used when the function is called through the `Derived Class` object.

In the example, `Employee1.Print()` calls the `Print()` inside `clsEmployee` instead of the inherited `Print()` inside `clsPerson`.

---

In this example, `Print()` exists in `clsPerson`, and another `Print()` exists in `clsEmployee`.

Both functions have the same name and the same signature.

So when we write:

`Employee1.Print();`

the `Print()` inside `clsEmployee` is used.

This version prints the `Person` data and also:

- `Title`
- `Department`
- `Salary`

---

## 📌 Why Do We Need Overriding?

The inherited `Print()` from `Person` does not contain code for the new `Employee` data.

So it is not enough for `Employee`.

With `Overriding`, we define `Print()` again inside `Employee` and write what fits `Employee`.

---

## ⚙️ Same Name and Same Signature

To use `Overriding` as shown here, the function name and the signature must match.

In the `Base Class`:

`void Print()`

In the `Derived Class`:

`void Print()`

When they match, the `Derived Class` version is used when the function is called through `Employee1`.

---

## 📌 Accessing the Original Function

Sometimes we may want to call the original function in the `Base Class`.

From the `Derived Class`, we use the `Base Class` name with `::` and then the function name:

`clsPerson::Print()`

This gives access to the original `Print()` inside `clsPerson`.

---

## 📌 Accessing Base Class Data

Variables such as:

`_ID`, `_FirstName`, `_LastName`, `_Email`, and `_Phone`

belong to `clsPerson` and are `private`.

So `clsEmployee` cannot access them directly.

Instead, the values are accessed through the functions available in `Person`, such as:

- `ID()`
- `FirstName()`
- `LastName()`
- `Email()`
- `Phone()`
- `FullName()`

This is the approach used inside the new `Print()`.

---

## 📌 Difference Between `Print()` in `Person` and `Employee`

The `Print()` in `Person` prints:

`ID`, `FirstName`, `LastName`, `FullName`, `Email`, and `Phone`.

The `Print()` in `Employee` prints the same data and also:

`Title`, `Department`, and `Salary`.

So the `Employee` version fits the `Employee` data.

---

## 📚 Terminology

| Term | Meaning |
|---|---|
| Function Overriding | Defining a new version of an inherited function with the same name and signature |
| Signature | The function name and its parameters |
| Base Class | The class that contains the original function |
| Derived Class | The class that defines the new version of the inherited function |
| `BaseClass::FunctionName()` | The syntax used to access the function in the `Base Class` |

---

## ⚠️ Notes

- The same function name and the same signature are used for the overriding shown here.
- `Employee1.Print()` calls the `Print()` inside `clsEmployee`.
- The original `Print()` in `clsPerson` still exists and can be accessed with `clsPerson::Print()`.
- `private` variables from `clsPerson` cannot be accessed directly from `clsEmployee`.
- These values are accessed through the available functions, such as `ID()`, `FirstName()`, and `Email()`.
- The new `Print()` in `Employee` also prints `Title`, `Department`, and `Salary`.

---

## 💡 Key Idea

`Inheritance` gave `Employee` the `Print()` function from `Person`.

But the original `Print()` does not fit the extra `Employee` data, so we define another `Print()` in `Employee` with the same name and the same signature.

This is `Function Overriding`.

---

## 🔑 Summary

- `Function Overriding` means defining a new version of an inherited function inside the `Derived Class`.
- The function name and signature match in the example.
- `Employee1.Print()` uses the `Print()` inside `Employee`.
- The original function can be accessed with:
  `clsPerson::Print()`
- `private` data from `Person` is not accessed directly.
- It is accessed through functions such as `ID()` and `FirstName()`.
- `Employee` can add its own output to the overridden `Print()`.
