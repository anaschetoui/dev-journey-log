# Virtual Functions

---

## 📝 مقدمة

عندما نستخدم `Inheritance` و`Function Overriding` يمكن أن تكون لدينا دالة مثل `()Print` في الـ `Base Class`، ثم نعيد تعريفها في الـ `Derived Classes`.

المشكلة تظهر عندما نستخدم `Base Class Pointer` يشير إلى كائن من `Derived Class`. هنا نحتاج إلى `virtual` حتى يتم استدعاء الدالة المناسبة للكائن الفعلي.

---

## 🧠 مراجعة سريعة

لدينا:

`Person` ← `Employee`

و:

`Person` ← `Student`

كل من `Employee` و`Student` ترث من `Person`، وكل واحدة منهما لديها `()Print` خاصة بها.

عند استدعاء `()Print` مباشرة من كائن `Employee` أو `Student`، يتم استخدام الدالة الموجودة في الكلاس المناسبة.

---

## 🎯 تعريف: Virtual Function

> **Virtual Function**
>
> دالة في الـ `Base Class` نضع قبلها الكلمة `virtual`، بحيث عند استخدام `Base Class Pointer` يشير إلى `Derived Class Object` يتم استدعاء الدالة الموجودة في الـ `Derived Class`.

---

## ⚙️ المشكلة بدون `virtual`

لدينا `()Print` في `Person`، ثم قمنا بعمل `Override` لها في `Employee` و`Student`.

إذا كان `Person Pointer` يشير إلى `Employee Object` أو `Student Object`، فإن `()Print` الموجودة في `Person` هي التي يتم استدعاؤها في المثال عندما لا تكون الدالة `virtual`.

أي أن نوع الـ `Pointer` يصبح مهمًا عند استدعاء الدالة بهذه الطريقة.

---

## 💻 مثال: Virtual Function

<div dir="ltr" style="text-align:left;font-family:'Arial',sans-serif;">

```cpp
#include <iostream>

using namespace std;

class clsPerson
{

public:

    virtual void Print()

    {
        cout << "Hi, i'm a person!\n ";

    }

};

class clsEmployee : public clsPerson
{
public:
    void Print()
    {
        cout << "Hi, I'm an Employee\n";
    }
};

class clsStudent : public clsPerson
{
public:
    void Print()
    {
        cout << "Hi, I'm a student\n";
    }
};

int main()
{
    clsEmployee Employee1;
    clsStudent Student1;

    Employee1.Print();
    Student1.Print();

    clsPerson* Person1 = &Employee1;
    clsPerson* Person2 = &Student1;

    Person1->Print();
    Person2->Print();

    system("pause>0");
    return 0;
}
```

</div>

عند كتابة:

`;()Employee1.Print`

يتم استدعاء `()Print` الموجودة في `Employee`.

وعند كتابة:

`;()Student1.Print`

يتم استدعاء `()Print` الموجودة في `Student`.

---

## ⚙️ استخدام `Base Class Pointer`

لدينا:

`clsPerson* Person1 = &Employee1;`

أي أن `Person1` من نوع `Person Pointer`، لكنه يشير إلى `Employee1`.

ولدينا أيضًا:

`;clsPerson* Person2 = &Student1`

أي أن `Person2` من نوع `Person Pointer`، لكنه يشير إلى `Student1`.

هذا هو نفس مفهوم `Up Casting` الذي أخذناه سابقًا.

---

## 📌 لماذا نستخدم `virtual`؟

في الكود:

`()virtual void Print`

نحدد أن `()Print` يمكن عمل `Override` لها في الـ `Derived Classes`.

عند وجود `Base Class Pointer` يشير إلى `Derived Class Object`، يتم استدعاء `()Print` المناسبة للكائن الفعلي.

لذلك:

`;()Person1->Print`

تستدعي:

`()Employee::Print`

و:

`;()Person2->Print`

تستدعي:

`()Student::Print`

---

## 📌 ماذا يحدث بدون `virtual`؟

إذا حذفنا:

`virtual`

من `()Print` في `clsPerson`، فإن:

`;()Person1->Print`

و:

`;()Person2->Print`

يستدعيان `()Print` الموجودة في `clsPerson` في هذا المثال.

والنتيجة تكون:

`Hi, i'm a person!`

في الحالتين.

---

## ⚙️ العلاقة بين `virtual` و`Function Overriding`

لدينا:

`()Person::Print`

ثم:

`()Employee::Print`

و:

`()Student::Print`

الدوال في الـ `Derived Classes` لها نفس الاسم ونفس الـ signature.

لكن عند استخدام `Person Pointer`، نحتاج إلى `virtual` حتى يتم استدعاء النسخة المناسبة من الـ `Derived Class`.

---

## 📌 Virtual Table

عند استخدام `virtual`، يشرح هذا المثال أن المترجم ينشئ `Virtual Table` في الذاكرة ويخزن فيها عناوين الدوال.

عندما يشير `Person Pointer` إلى `Employee` أو `Student`، يتم استخدام هذه المعلومات للوصول إلى `()Print` المناسبة.

---

## 📌 الفرق بين الاستدعاء من Object والاستدعاء من Pointer

عند كتابة:

`;()Employee1.Print`

الـ `Object` من نوع `Employee`، لذلك يتم استدعاء `()Employee::Print`.

أما عند كتابة:

`Person1->Print();`

فالـ `Pointer` من نوع `Person`.

هنا تظهر أهمية `virtual` حتى يتم استدعاء `()Print` الخاصة بالكائن الفعلي.

---

## 📚 المصطلحات

| المصطلح | المعنى |
|---|---|
| Virtual Function | دالة في الـ `Base Class` تسمح باستدعاء الدالة المعاد تعريفها في الـ `Derived Class` عند استخدام `Base Class Pointer` |
| Function Overriding | إعادة كتابة دالة موروثة بنفس الاسم ونفس الـ signature بتنفيذ جديد |
| Base Class Pointer | `Pointer` من نوع الـ `Base Class` |
| Virtual Table | جدول في الذاكرة يحتوي على عناوين الدوال المرتبطة بالـ `virtual` |

---

## ⚠️ ملاحظات

- نضع `virtual` في دالة الـ `Base Class`.
- يمكن عمل `Override` للدالة في الـ `Derived Classes`.
- تظهر أهمية `virtual` عند استخدام `Base Class Pointer`.
- `Person1` يشير إلى `Employee1`.
- `Person2` يشير إلى `Student1`.
- بدون `virtual` يتم استدعاء `()Print` الموجودة في `Person` في المثال.
- مع `virtual` يتم استدعاء `()Print` المناسبة للكائن الفعلي.
- `Pure Virtual Functions` ليست ضمن تفاصيل هذا الدرس.

---

## 💡 الفكرة الأساسية

عندما يكون لدينا:

`Base Class Pointer → Derived Class Object`

فإن `virtual` تجعل الدالة المعاد تعريفها في الـ `Derived Class` هي التي يتم استدعاؤها.

في المثال:

`Person1 → Employee1`

لذلك:

`;()Person1->Print`

تستدعي `()Employee::Print`.

وكذلك:

`Person2 → Student1`

تستدعي `()Student::Print`.

---

## 🔑 ملخص

- `Virtual Function` هي دالة تحتوي على كلمة `virtual` في الـ `Base Class`.
- تستخدم مع `Inheritance` و`Function Overriding`.
- أهميتها تظهر عند استخدام `Base Class Pointer`.
- يمكن لـ `Person Pointer` أن يشير إلى `Employee` أو `Student`.
- بدون `virtual` يتم استدعاء `()Print` الخاصة بـ `Person` في المثال.
- مع `virtual` يتم استدعاء `()Print` الخاصة بالنوع الفعلي للكائن.

## 📝 Introduction

With `Inheritance` and `Function Overriding`, we can have a function such as `Print()` in the `Base Class`, then override it in the `Derived Classes`.

The problem appears when a `Base Class Pointer` points to a `Derived Class Object`. Here we need `virtual` so the function for the real object is called.

---

## 🧠 Quick Recap

We have:

`Person` ← `Employee`

and:

`Person` ← `Student`

Both `Employee` and `Student` inherit from `Person`, and both have their own `Print()`.

When we call `Print()` directly from an `Employee` or `Student` object, the function in the correct class is used.

---

## 🎯 Definition: Virtual Function

> **Virtual Function**
>
> A function in the `Base Class` with the `virtual` keyword. When a `Base Class Pointer` points to a `Derived Class Object`, the overridden function in the `Derived Class` can be called.

---

## ⚙️ The Problem Without `virtual`

We have `Print()` in `Person`, and we override it in `Employee` and `Student`.

If a `Person Pointer` points to an `Employee Object` or a `Student Object`, the `Print()` in `Person` is called in the example when the function is not `virtual`.

So the pointer type becomes important in this case.

---

## 💻 Example: Virtual Function

```cpp
#include <iostream>

using namespace std;

class clsPerson
{

public:

    virtual void Print()

    {
        cout << "Hi, i'm a person!\n ";

    }

};

class clsEmployee : public clsPerson
{
public:
    void Print()
    {
        cout << "Hi, I'm an Employee\n";
    }
};

class clsStudent : public clsPerson
{
public:
    void Print()
    {
        cout << "Hi, I'm a student\n";
    }
};

int main()
{
    clsEmployee Employee1;
    clsStudent Student1;

    Employee1.Print();
    Student1.Print();

    clsPerson* Person1 = &Employee1;
    clsPerson* Person2 = &Student1;

    Person1->Print();
    Person2->Print();

    system("pause>0");
    return 0;
}
```

The call:

`Employee1.Print();`

uses `Print()` from `Employee`.

The call:

`Student1.Print();`

uses `Print()` from `Student`.

---

## ⚙️ Using a `Base Class Pointer`

We have:

`clsPerson* Person1 = &Employee1;`

So `Person1` is a `Person Pointer`, but it points to `Employee1`.

We also have:

`clsPerson* Person2 = &Student1;`

So `Person2` is a `Person Pointer`, but it points to `Student1`.

This is the same `Up Casting` idea we learned before.

---

## 📌 Why Do We Use `virtual`?

In the code:

`virtual void Print()`

we say that `Print()` can be overridden in the `Derived Classes`.

When a `Base Class Pointer` points to a `Derived Class Object`, the correct `Print()` for the real object is called.

So:

`Person1->Print();`

calls:

`Employee::Print()`

and:

`Person2->Print();`

calls:

`Student::Print()`

---

## 📌 What Happens Without `virtual`?

If we remove:

`virtual`

from `Print()` in `clsPerson`, then:

`Person1->Print();`

and:

`Person2->Print();`

call the `Print()` in `clsPerson` in this example.

The result is:

`Hi, i'm a person!`

for both calls.

---

## ⚙️ `virtual` and Function Overriding

We have:

`Person::Print()`

then:

`Employee::Print()`

and:

`Student::Print()`

The functions in the `Derived Classes` have the same name and the same signature.

But when we use `Person` pointers, we need `virtual` so the correct `Derived Class` version is called.

---

## 📌 Virtual Table

With `virtual`, this example explains that the compiler creates a `Virtual Table` in memory and stores function addresses in it.

When a `Person Pointer` points to an `Employee` or `Student`, this information is used to reach the correct `Print()`.

---

## 📌 Object Call vs Pointer Call

When we write:

`Employee1.Print();`

the object is an `Employee`, so `Employee::Print()` is called.

But when we write:

`Person1->Print();`

the pointer type is `Person`.

This is where `virtual` becomes important, because it makes the call reach the `Print()` for the real object.

---

## 📚 Terminology

| Term | Meaning |
|---|---|
| Virtual Function | A `Base Class` function that allows the overridden `Derived Class` function to be called through a `Base Class Pointer` |
| Function Overriding | Writing a new version of an inherited function with the same name and signature |
| Base Class Pointer | A `Pointer` whose type is the `Base Class` |
| Virtual Table | A table in memory that contains addresses related to `virtual` functions |

---

## ⚠️ Notes

- We put `virtual` on the function in the `Base Class`.
- The function can be overridden in the `Derived Classes`.
- `virtual` becomes important when using a `Base Class Pointer`.
- `Person1` points to `Employee1`.
- `Person2` points to `Student1`.
- Without `virtual`, `Person::Print()` is called in this example.
- With `virtual`, the correct function for the real object is called.
- `Pure Virtual Functions` are not covered in this lesson.

---

## 💡 Key Idea

When we have:

`Base Class Pointer → Derived Class Object`

`virtual` makes the overridden `Derived Class` function the function that is called.

In the example:

`Person1 → Employee1`

so:

`Person1->Print();`

calls `Employee::Print()`.

Also:

`Person2 → Student1`

calls `Student::Print()`.

---

## 🔑 Summary

- A `Virtual Function` is a function with the `virtual` keyword in the `Base Class`.
- It is used with `Inheritance` and `Function Overriding`.
- It is especially important with a `Base Class Pointer`.
- A `Person Pointer` can point to an `Employee` or `Student`.
- Without `virtual`, `Person::Print()` is called in the example.
- With `virtual`, the function for the real object is called.
