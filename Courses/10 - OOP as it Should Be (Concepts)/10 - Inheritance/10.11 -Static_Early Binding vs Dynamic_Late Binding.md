# Static Binding vs Dynamic Binding

---

## 📝 مقدمة

عند استدعاء دالة في C++، يمكن أن يكون ربط الاستدعاء معروفًا أثناء `Compile Time` أو يتم تحديده أثناء `Runtime`.

`Static Binding` و`Early Binding` هما اسمان لنفس المفهوم، وكذلك `Dynamic Binding` و`Late Binding` هما اسمان لنفس المفهوم.

---

## 🧠 مراجعة سريعة

لدينا `clsPerson` وهي `Base Class`.

ولدينا:

`clsEmployee : public clsPerson`

و:

`clsStudent : public clsPerson`

وكل من `Employee` و`Student` لديهما `()Print` خاصة بهما.

كما استخدمنا `Person Pointer` يشير إلى `Employee` أو `Student` مع `virtual`.

---

## 🎯 تعريف: Static Binding / Early Binding

> **Static Binding / Early Binding**
>
> ربط استدعاء الدالة أثناء `Compile Time` عندما يكون نوع الكائن معروفًا مسبقًا للمترجم.

---

## ⚙️ كيف يعمل Static Binding؟

عند كتابة:

`;()Employee1.Print`

نعرف أن `Employee1` من نوع `clsEmployee`.

وعند كتابة:

`;()Student1.Print`

نعرف أن `Student1` من نوع `clsStudent`.

لذلك يستطيع المترجم معرفة الدالة التي سيتم استدعاؤها أثناء `Compile Time`.

أي:

`()Employee1.Print` → `()Employee::Print`

`()Student1.Print` → `()Student::Print`

ولهذا يسمى:

`Static Binding`

أو:

`Early Binding`

---

## 💻 مثال: Static Binding

<div dir="ltr" style="text-align:left;font-family:'Arial',sans-serif;">

```cpp
#include <iostream>

using namespace std;

class clsPerson
{
public:

    virtual void Print()
    {
        cout << "Hi, i'm a person!\n ";
    }
};

class clsEmployee : public clsPerson
{
public:

    void Print()
    {
        cout << "Hi, I'm an Employee\n";
    }
};

class clsStudent : public clsPerson
{
public:

    void Print()
    {
        cout << "Hi, I'm a student\n";
    }
};

int main()
{
    clsEmployee Employee1;
    clsStudent Student1;

    //Early-Static Binding: at compilation time
    Employee1.Print();
    Student1.Print();

    clsPerson* Person1 = &Employee1;
    clsPerson* Person2 = &Student1;

    //Late-Dynamic Binding: at runtime
    Person1->Print();
    Person2->Print();

    system("pause>0");
    return 0;
}
```

</div>

الاستدعاء المباشر من `Employee1` أو `Student1` يعتمد على النوع المعروف للكائن نفسه.

---

## 🎯 تعريف: Dynamic Binding / Late Binding

> **Dynamic Binding / Late Binding**
>
> ربط استدعاء الدالة أثناء `Runtime` عندما يتم تحديد الدالة المناسبة أثناء تشغيل البرنامج.

---

## ⚙️ كيف يعمل Dynamic Binding؟

لدينا:

`;clsPerson* Person1 = &Employee1`

إذن `Person1` من نوع `Person Pointer`، لكنه يشير إلى `Employee1`.

ولدينا:

`;clsPerson* Person2 = &Student1`

إذن `Person2` من نوع `Person Pointer`، لكنه يشير إلى `Student1`.

عند كتابة:

`;()Person1->Print`

يتم تحديد `()Print` المناسبة أثناء `Runtime`.

فتكون النتيجة:

`Person1->Print` → `Employee::Print`

وعند كتابة:

`Person2->Print`

تكون النتيجة:

`Person2->Print` → `Student::Print`

---

## 📌 لماذا نحتاج إلى `virtual`؟

في `clsPerson` لدينا:

`virtual void Print()`

كلمة `virtual` تجعل المترجم يتعامل مع `Print()` كدالة يمكن أن يتم عمل `Override` لها في الـ `Derived Classes`.

عند استخدام `Base Class Pointer`، تساعد `virtual` على الوصول إلى الدالة المناسبة للكائن الفعلي.

---

## 📌 ماذا يحدث بدون `virtual`؟

إذا حذفنا `virtual` من:

`()clsPerson::Print`

فإن الاستدعاء:

`()Person1->Print`

و:

`()Person2->Print`

يستخدم `()Print` الموجودة في `clsPerson` في المثال.

أي أن الناتج يصبح:

`Hi, i'm a person!`

في الحالتين.

---

## ⚙️ Compile Time مقابل Runtime

| النوع | متى يتم الربط؟ | المثال |
|---|---|---|
| `Static Binding` / `Early Binding` | أثناء `Compile Time` | `()Employee1.Print` |
| `Dynamic Binding` / `Late Binding` | أثناء `Runtime` | `()Person1->Print` |

---

## 📌 العلاقة بين Static وEarly

`Static Binding`

و:

`Early Binding`

هما اسمان لنفس المفهوم.

الفكرة هي أن المترجم يعرف الدالة المطلوبة مبكرًا، أثناء `Compile Time`.

---

## 📌 العلاقة بين Dynamic وLate

`Dynamic Binding`

و:

`Late Binding`

هما اسمان لنفس المفهوم.

الفكرة هي أن تحديد الدالة يتم لاحقًا، أثناء `Runtime`.

---

## 📚 المصطلحات

| المصطلح | المعنى |
|---|---|
| Static Binding | ربط الدالة أثناء `Compile Time` |
| Early Binding | اسم آخر لـ `Static Binding` |
| Dynamic Binding | ربط الدالة أثناء `Runtime` |
| Late Binding | اسم آخر لـ `Dynamic Binding` |
| Compile Time | وقت ترجمة البرنامج |
| Runtime | وقت تشغيل البرنامج |

---

## ⚠️ ملاحظات

- `Static Binding = Early Binding`.
- `Dynamic Binding = Late Binding`.
- `()Employee1.Print` و`()Student1.Print` يمثلان `Early Binding`.
- `()Person1->Print` و`()Person2->Print` يمثلان `Late Binding` مع `virtual`.
- استخدام `Base Class Pointer` هو النقطة التي يظهر فيها الفرق بوضوح.
- مع `virtual` يتم استدعاء `()Print` المناسبة للكائن الفعلي.

---

## 💡 الفكرة الأساسية

إذا كان نوع الكائن معروفًا أثناء `Compile Time`، فلدينا:

`Static / Early Binding`

أما عند استخدام `Base Class Pointer` مع `virtual`، ويتم اختيار الدالة أثناء `Runtime`، فلدينا:

`Dynamic / Late Binding`

---

## 🔑 ملخص

- `Static Binding` و`Early Binding` هما نفس المفهوم.
- `Dynamic Binding` و`Late Binding` هما نفس المفهوم.
- `Early Binding` يحدث أثناء `Compile Time`.
- `Late Binding` يحدث أثناء `Runtime`.
- الاستدعاء `()Employee1.Print` معروف من نوع الكائن.
- الاستدعاء `()Person1->Print` يحتاج إلى `virtual` حتى يتم اختيار الدالة المناسبة للكائن الفعلي.

## 📝 Introduction

When we call a function in C++, the call can be bound at `Compile Time` or selected at `Runtime`.

`Static Binding` and `Early Binding` mean the same thing. `Dynamic Binding` and `Late Binding` also mean the same thing.

---

## 🧠 Quick Recap

We have `clsPerson` as the `Base Class`.

We also have:

`clsEmployee : public clsPerson`

and:

`clsStudent : public clsPerson`

Both `Employee` and `Student` have their own `Print()`.

We also use `Person Pointer` objects that point to `Employee` and `Student` with `virtual`.

---

## 🎯 Definition: Static Binding / Early Binding

> **Static Binding / Early Binding**
>
> Binding the function call at `Compile Time` when the object type is already known to the compiler.

---

## ⚙️ How Does Static Binding Work?

When we write:

`Employee1.Print();`

we know that `Employee1` is a `clsEmployee`.

When we write:

`Student1.Print();`

we know that `Student1` is a `clsStudent`.

So the compiler can know which function should be called at `Compile Time`.

So:

`Employee1.Print()` → `Employee::Print()`

`Student1.Print()` → `Student::Print()`

This is:

`Static Binding`

or:

`Early Binding`

---

## 💻 Example: Static Binding

```cpp
#include <iostream>

using namespace std;

class clsPerson
{
public:

    virtual void Print()
    {
        cout << "Hi, i'm a person!\n ";
    }
};

class clsEmployee : public clsPerson
{
public:

    void Print()
    {
        cout << "Hi, I'm an Employee\n";
    }
};

class clsStudent : public clsPerson
{
public:

    void Print()
    {
        cout << "Hi, I'm a student\n";
    }
};

int main()
{
    clsEmployee Employee1;
    clsStudent Student1;

    //Early-Static Binding: at compilation time
    Employee1.Print();
    Student1.Print();

    clsPerson* Person1 = &Employee1;
    clsPerson* Person2 = &Student1;

    //Late-Dynamic Binding: at runtime
    Person1->Print();
    Person2->Print();

    system("pause>0");
    return 0;
}
```

A direct call from `Employee1` or `Student1` uses the type already known for the object.

---

## 🎯 Definition: Dynamic Binding / Late Binding

> **Dynamic Binding / Late Binding**
>
> Binding the function call at `Runtime` when the correct function is selected while the program is running.

---

## ⚙️ How Does Dynamic Binding Work?

We have:

`clsPerson* Person1 = &Employee1;`

So `Person1` is a `Person Pointer`, but it points to `Employee1`.

We also have:

`clsPerson* Person2 = &Student1;`

So `Person2` is a `Person Pointer`, but it points to `Student1`.

When we write:

`Person1->Print();`

the correct `Print()` is selected at `Runtime`.

So:

`Person1->Print()` → `Employee::Print()`

And:

`Person2->Print()` → `Student::Print()`

---

## 📌 Why Do We Need `virtual`?

In `clsPerson` we have:

`virtual void Print()`

The `virtual` keyword tells the compiler that `Print()` can be overridden in the `Derived Classes`.

When we use a `Base Class Pointer`, `virtual` helps call the correct function for the real object.

---

## 📌 What Happens Without `virtual`?

If we remove `virtual` from:

`clsPerson::Print()`

then:

`Person1->Print()`

and:

`Person2->Print()`

call `Print()` from `clsPerson` in the example.

The result becomes:

`Hi, i'm a person!`

for both calls.

---

## ⚙️ Compile Time vs Runtime

| Type | When is the call bound? | Example |
|---|---|---|
| `Static Binding` / `Early Binding` | At `Compile Time` | `Employee1.Print()` |
| `Dynamic Binding` / `Late Binding` | At `Runtime` | `Person1->Print()` |

---

## 📌 Static and Early

`Static Binding`

and:

`Early Binding`

mean the same thing.

The compiler knows the required function early, at `Compile Time`.

---

## 📌 Dynamic and Late

`Dynamic Binding`

and:

`Late Binding`

mean the same thing.

The function is selected later, at `Runtime`.

---

## 📚 Terminology

| Term | Meaning |
|---|---|
| Static Binding | Binding the function at `Compile Time` |
| Early Binding | Another name for `Static Binding` |
| Dynamic Binding | Binding the function at `Runtime` |
| Late Binding | Another name for `Dynamic Binding` |
| Compile Time | The time when the program is compiled |
| Runtime | The time when the program is running |

---

## ⚠️ Notes

- `Static Binding = Early Binding`.
- `Dynamic Binding = Late Binding`.
- `Employee1.Print()` and `Student1.Print()` show `Early Binding`.
- `Person1->Print()` and `Person2->Print()` show `Late Binding` with `virtual`.
- The difference becomes clear when using a `Base Class Pointer`.
- With `virtual`, the correct function for the real object is called.

---

## 💡 Key Idea

If the object type is known at `Compile Time`, we have:

`Static / Early Binding`

When we use a `Base Class Pointer` with `virtual` and the function is selected at `Runtime`, we have:

`Dynamic / Late Binding`

---

## 🔑 Summary

- `Static Binding` and `Early Binding` mean the same thing.
- `Dynamic Binding` and `Late Binding` mean the same thing.
- `Early Binding` happens at `Compile Time`.
- `Late Binding` happens at `Runtime`.
- `Employee1.Print()` is known from the object type.
- `Person1->Print()` needs `virtual` so the correct function for the real object is called.
