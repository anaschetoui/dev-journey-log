# Multilevel Inheritance

---

## 📝 مقدمة

`Multilevel Inheritance` هي حالة يكون فيها لدينا أكثر من مستوى من الوراثة.

في هذا المثال، `clsEmployee` ترث من `clsPerson`، ثم `clsDeveloper` ترث من `clsEmployee`.

وبذلك تستفيد `Developer` من الأعضاء الموجودة في `Employee` ومن الأعضاء الموروثة إلى `Employee` من `Person`.

---

## 🧠 مراجعة سريعة

`Employee` ترث من `Person`.

في هذا الدرس نضيف مستوى جديدًا: `Developer` ترث من `Employee`.

إذن تصبح السلسلة:

`Person → Employee → Developer`

---

## 🎯 تعريف: Multilevel Inheritance

> **Multilevel Inheritance**
>
> وراثة تتم عبر أكثر من مستوى، بحيث ترث `Class` من `Class` أخرى، ثم ترث `Class` ثالثة من الكلاس الوارثة الأولى.

---

## ⚙️ كيف تعمل Multilevel Inheritance؟

لدينا ثلاث كلاسات:

`clsPerson`

هي الكلاس الأصلية.

ثم:

`clsEmployee : public clsPerson`

فتصبح `Employee` وارثة من `Person`.

ثم:

`clsDeveloper : public clsEmployee`

فتصبح `Developer` وارثة من `Employee`.

لذلك تصل أعضاء `Person` إلى `Developer` عبر `Employee`.

---

## 📌 ماذا تضيف كل Class؟

`Person` تحتوي على بيانات مثل:

- `ID`
- `FirstName`
- `LastName`
- `Email`
- `Phone`

وتحتوي أيضًا على دوال مثل `()FullName` و`()Print` و`()SendEmail` و`()SendSMS`.

`Employee` تضيف:

- `Title`
- `Department`
- `Salary`

`Developer` تضيف:

- `MainProgrammingLanguage`

لا نعيد كتابة أعضاء `Person` داخل `Employee`، ولا نعيد كتابة أعضاء `Person` و`Employee` داخل `Developer`.

---

## ⚙️ Syntax إنشاء Multilevel Inheritance

المستوى الأول:

<div dir="ltr" style="text-align:left;font-family:'Arial',sans-serif;">

```cpp
class clsEmployee : public clsPerson
{
};
```

</div>

المستوى الثاني:

<div dir="ltr" style="text-align:left;font-family:'Arial',sans-serif;">

```cpp
class clsDeveloper : public clsEmployee
{
};
```

</div>

السلسلة تصبح:

`clsPerson → clsEmployee → clsDeveloper`

---

## ⚙️ Constructors في Multilevel Inheritance

كل مستوى في المثال لديه `Parameterized Constructor`.

`clsPerson` تستقبل بيانات الشخص.

`clsEmployee` تستقبل بيانات `Person` بالإضافة إلى `Title` و`Department` و`Salary`، ثم تمرر بيانات `Person` إلى `clsPerson`.

`clsDeveloper` تستقبل كل البيانات المطلوبة، ثم تمرر بيانات `Employee` إلى `clsEmployee`، وتقوم بتهيئة `MainProgrammingLanguage`.

---

## 📌 كيف تنتقل البيانات بين المستويات؟

عند إنشاء `Developer1`، يتم إرسال جميع البيانات إلى `clsDeveloper`.

ثم يرسل `clsDeveloper` بيانات `Person` و`Employee` إلى `clsEmployee` من خلال الـ `Constructor Initializer List`.

بعد ذلك يرسل `clsEmployee` بيانات `Person` إلى `clsPerson`.

فتنتقل البيانات عبر السلسلة:

`Developer → Employee → Person`

---

## 📌 ماذا يرث Developer؟

`Developer` ترث من `Employee`، و`Employee` ترث من `Person`.

لذلك يستطيع `Developer1` استخدام أعضاء من المستويات الثلاثة.

من `Person` مثل:

`()ID` و`()FirstName` و`()LastName` و`()FullName` و`()Email` و`()Phone` و`()SendEmail` و`()SendSMS`.

ومن `Employee` مثل:

`()Title` و`()Department` و`()Salary`.

ومن `Developer`:

`()MainProgrammingLanguage`.

---

## 📌 إضافة عضو مشترك

إذا أضفنا دالة مشتركة مثل `()SendFax` إلى `Person`، فإن الكلاسات التي ترث من `Person` يمكنها الاستفادة منها.

لذلك لا نحتاج إلى كتابة الدالة نفسها داخل `Employee` و`Developer`.

---

## 📌 الفائدة في المشاريع الكبيرة

كلما كبر المشروع، تزيد قيمة إعادة استخدام الكود.

في `Multilevel Inheritance`:

- يبقى الكود المشترك في المستوى المناسب.
- كل مستوى يضيف ما يخصه فقط.
- يمكن تعديل الكود المشترك في مكان واحد.
- تقل إعادة كتابة الكود.
- تتحسن `Reusability` و`Maintainability`.

---

## 📚 المصطلحات

| المصطلح | المعنى |
|---|---|
| Multilevel Inheritance | وراثة تتم عبر أكثر من مستوى |
| Inheritance Level | مستوى من مستويات الوراثة |
| Base Class | الكلاس الأصلية التي يتم الوراثة منها |
| Derived Class | الكلاس التي ترث من كلاس أخرى |
| Maintainability | سهولة تعديل الكود وصيانته |
| Reusability | إعادة استخدام الكود بدل كتابته مرة أخرى |

---

## ⚠️ ملاحظات

- `clsDeveloper` ترث `clsEmployee`.
- `clsEmployee` ترث `clsPerson`.
- لذلك `Developer` تستفيد من أعضاء `Employee` و`Person`.
- كل `Constructor` يمرر بيانات المستوى الأعلى إلى الـ `Base Class` المناسبة.
- يمكن أن توجد مستويات متعددة من الوراثة حسب حاجة المشروع.
- لا نعيد كتابة الأعضاء الموروثة في كل مستوى.
- في المثال، `Developer` تضيف `MainProgrammingLanguage` إلى ما تم توريثه.

---

## 💡 الفكرة الأساسية

بدل أن نكتب الكود نفسه في `Person` و`Employee` و`Developer`، نبني سلسلة وراثة:

`Person → Employee → Developer`

فتستفيد `Developer` من الكود الموروث من المستويين السابقين، وتضيف فقط الأعضاء الخاصة بها.

---

## 🔑 ملخص

- `Multilevel Inheritance` تعني وجود أكثر من مستوى في سلسلة الوراثة.
- `Employee` ترث من `Person`.
- `Developer` ترث من `Employee`.
- لذلك `Developer` تستفيد من أعضاء `Person` و`Employee`.
- كل `Constructor` يمرر البيانات إلى الـ `Base Class` المناسبة.
- `Developer` تضيف `MainProgrammingLanguage` في هذا المثال.
- هذا الأسلوب يقلل إعادة كتابة الكود ويحسن `Reusability` و`Maintainability`.

## 📝 Introduction

`Multilevel Inheritance` is a case where we have more than one inheritance level.

In this example, `clsEmployee` inherits from `clsPerson`, and `clsDeveloper` inherits from `clsEmployee`.

So `Developer` can use the code in `Employee`, and `Employee` already uses the code inherited from `Person`.

---

## 🧠 Quick Recap

`Employee` inherits from `Person`.

In this lesson, we add another level: `Developer` inherits from `Employee`.

So the chain becomes:

`Person → Employee → Developer`

---

## 🎯 Definition: Multilevel Inheritance

> **Multilevel Inheritance**
>
> Inheritance with more than one level, where one `Class` inherits from another `Class`, and another `Class` inherits from the first derived class.

---

## ⚙️ How Multilevel Inheritance Works

We have three classes:

`clsPerson`

This is the original class.

Then:

`clsEmployee : public clsPerson`

So `Employee` inherits from `Person`.

Then:

`clsDeveloper : public clsEmployee`

So `Developer` inherits from `Employee`.

Therefore, the members of `Person` reach `Developer` through `Employee`.

---

## 📌 What Does Each Class Add?

`Person` has data such as:

- `ID`
- `FirstName`
- `LastName`
- `Email`
- `Phone`

It also has functions such as `FullName()`, `Print()`, `SendEmail()`, and `SendSMS()`.

`Employee` adds:

- `Title`
- `Department`
- `Salary`

`Developer` adds:

- `MainProgrammingLanguage`

We do not rewrite `Person` members inside `Employee`, and we do not rewrite `Person` and `Employee` members inside `Developer`.

---

## ⚙️ Syntax for Multilevel Inheritance

First level:

```cpp
class clsEmployee : public clsPerson
{
};
```

Second level:

```cpp
class clsDeveloper : public clsEmployee
{
};
```

So the chain is:

`clsPerson → clsEmployee → clsDeveloper`

---

## ⚙️ Constructors in Multilevel Inheritance

Each level in this example has a `Parameterized Constructor`.

`clsPerson` receives the person data.

`clsEmployee` receives the `Person` data plus `Title`, `Department`, and `Salary`, then passes the `Person` data to `clsPerson`.

`clsDeveloper` receives all required data, passes the `Employee` data to `clsEmployee`, and initializes `MainProgrammingLanguage`.

---

---

## 📌 What Does Developer Inherit?

`Developer` inherits from `Employee`, and `Employee` inherits from `Person`.

So `Developer1` can use members from all three levels.

From `Person`:

`ID()`, `FirstName()`, `LastName()`, `FullName()`, `Email()`, `Phone()`, `SendEmail()`, and `SendSMS()`.

From `Employee`:

`Title()`, `Department()`, and `Salary()`.

From `Developer`:

`MainProgrammingLanguage()`.

---

## 📌 Adding a Shared Member

If we add a shared function such as `SendFax()` to `Person`, classes that inherit from `Person` can use it.

We do not need to rewrite the same function inside `Employee` and `Developer`.

---

## 📌 Benefit in Large Projects

As a project becomes larger, code reuse becomes more useful.

With `Multilevel Inheritance`:

- Shared code stays in the suitable level.
- Each level adds only what belongs to it.
- Shared code can be changed in one place.
- Repeated code is reduced.
- `Reusability` and `Maintainability` improve.

---

## 📚 Terminology

| Term | Meaning |
|---|---|
| Multilevel Inheritance | Inheritance through more than one level |
| Inheritance Level | One level in an inheritance chain |
| Base Class | The original class that another class inherits from |
| Derived Class | A class that inherits from another class |
| Maintainability | How easy it is to change and maintain code |
| Reusability | Reusing code instead of writing it again |

---

## ⚠️ Notes

- `clsDeveloper` inherits from `clsEmployee`.
- `clsEmployee` inherits from `clsPerson`.
- So `Developer` can use members from `Employee` and `Person`.
- Each constructor passes data for the higher level to its `Base Class` constructor.
- There can be multiple inheritance levels when the project needs them.
- We do not rewrite inherited members at every level.
- In this example, `Developer` adds `MainProgrammingLanguage` to the inherited code.

---

## 💡 Key Idea

Instead of writing the same code in `Person`, `Employee`, and `Developer`, we build an inheritance chain:

`Person → Employee → Developer`

`Developer` can use the inherited code from the two levels above and add only its own members.

---

## 🔑 Summary

- `Multilevel Inheritance` means there is more than one inheritance level.
- `Employee` inherits from `Person`.
- `Developer` inherits from `Employee`.
- So `Developer` can use members from `Person` and `Employee`.
- Each constructor passes the required data to the correct `Base Class`.
- `Developer` adds `MainProgrammingLanguage` in this example.
- This approach reduces repeated code and improves `Reusability` and `Maintainability`.
