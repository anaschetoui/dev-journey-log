# Access Specifiers with Inheritance

---

## 📝 مقدمة

سبق أن تعرّفنا على `private` و`protected` و`public`، لكن استخدام `protected` يصبح أوضح عند الجمع بينه وبين `Inheritance`.

الفكرة الأساسية في هذا الدرس هي معرفة ما يستطيع الـ `Object` الوصول إليه من الخارج، وما تستطيع الـ `Derived Class` الوصول إليه من داخلها.

---

## 🧠 مراجعة سريعة

لدينا ثلاثة `Access Specifiers`:

- `private`
- `protected`
- `public`

`private` متاح داخل الـ `Class` نفسها فقط.

`public` متاح من الخارج، وداخل الـ `Class`، ومن الـ `Derived Classes`.

أما `protected` فهو متاح داخل الـ `Class` والـ `Derived Classes`، لكنه غير متاح مباشرة من الخارج.

---

## 🎯 تعريف: Protected with Inheritance

> **protected**
>
> عضو يكون غير متاح مباشرة من خارج الـ `Class`، لكنه متاح داخل الـ `Base Class` وجميع الـ `Derived Classes` التي ترث منها.

---

## ⚙️ الفرق بين private و protected

إذا كان لدينا:

`private int _Var1`

فلا تستطيع الـ `Derived Class` الوصول إليه مباشرة.

أما إذا كان لدينا:

`protected int Var2`

فإن الـ `Derived Class` تستطيع الوصول إليه من داخلها.

لذلك الفرق المهم هو:

`private` → لا يصل إليه الـ `Derived Class` مباشرة.

`protected` → يصل إليه الـ `Derived Class` من داخلها.

كلاهما غير متاح مباشرة من الخارج باستخدام `Object`.

---

## 💻 مثال: `clsA` و`clsB`

<div dir="ltr" style="text-align:left;font-family:'Arial',sans-serif;">

```cpp
#include <iostream>

using namespace std;

class clsA
{
private:
    // only accessible inside this class
    int _Var1;

    void _Fun1()
    {
        cout << "Function 1";
    }

protected:
    // only accessible inside this class and all derived classes
    int Var2;

    void Fun2()
    {
        cout << "Function 1";
    }

public:
    // Accessible inside this class, all derived classes, and outside
    int Var3;

    void Fun3()
    {
        cout << "Function 1";
    }
};

class clsB : public clsA
{
public:

    void Func1()
    {
        cout << clsA::Var2;
    }
};

int main()
{
    system("pause>0");
    return 0;
}
```

</div>

في `clsA` توجد ثلاثة مستويات:

- `_Var1` و`()_Fun1` تحت `private`.
- `Var2` و`()Fun2` تحت `protected`.
- `Var3` و`()Fun3` تحت `public`.

---

## 📌 ماذا يرى الـ Object من الخارج؟

إذا أنشأنا `Object` من `clsA` واستخدمنا `.` للوصول إلى الأعضاء، يمكن الوصول إلى الأعضاء `public` فقط.

إذن:

- `Var3` يمكن الوصول إليه.
- `()Fun3` يمكن الوصول إليها.
- `Var2` لا يمكن الوصول إليه.
- `()Fun2` لا يمكن الوصول إليها.
- `_Var1` لا يمكن الوصول إليه.
- `()_Fun1` لا يمكن الوصول إليها.

وجود العضو داخل `Class` لا يعني أنه متاح دائمًا من الخارج. مستوى الوصول هو الذي يحدد ذلك.

---

## ⚙️ ماذا ترى `clsB`؟

`clsB` ترث من `clsA`:

`class clsB : public clsA`

داخل `clsB` يمكن الوصول إلى:

- `Var2` لأنه `protected`.
- `()Fun2` لأنها `protected`.
- `Var3` لأنه `public`.
- `()Fun3` لأنها `public`.

لكن لا يمكن الوصول إلى:

- `_Var1`
- `()_Fun1`

لأنهما `private` في `clsA`.

---

## 📌 الوصول إلى `protected` من الـ Derived Class

في `clsB` لدينا:

`;cout << clsA::Var2`

هنا نستخدم اسم الـ `Base Class` مع `::` للوصول إلى `Var2`.

السبب هو أن `Var2` عضو `protected` في `clsA`، وبالتالي يمكن للـ `Derived Class` الوصول إليه.

---

## 📌 لماذا لا نجعل كل شيء public؟

أحيانًا نحتاج إلى متغيّر أو دالة تستطيع الـ `Derived Classes` استخدامها، لكننا لا نريد أن يستطيع المستخدم الخارجي الوصول إليها من خلال الـ `Object`.

هنا يكون `protected` مناسبًا.

مثلًا، إذا أردنا أن تستخدم `clsB`:

`Var2`

لكن لا نريد أن يستطيع مستخدم `clsA` الوصول إليه هكذا:

`A1.Var2`

فيمكن تعريفه كـ `protected`.

---

## 📌 قاعدة مهمة

يمكن تلخيص الوصول بهذه الصورة:

| Access Specifier | داخل الـ Class | من الخارج | Derived Class |
|---|---|---|---|
| `private` | نعم | لا | لا |
| `protected` | نعم | لا | نعم |
| `public` | نعم | نعم | نعم |

---

## 📚 المصطلحات

| المصطلح | المعنى |
|---|---|
| protected | عضو يمكن الوصول إليه من الـ `Class` والـ `Derived Classes` وليس من الخارج |
| private | عضو يمكن الوصول إليه من داخل الـ `Class` نفسها فقط |
| public | عضو يمكن الوصول إليه من الخارج ومن داخل الـ `Class` والـ `Derived Classes` |
| Base Class | الكلاس التي يتم الوراثة منها |
| Derived Class | الكلاس التي ترث من `Base Class` |

---

## ⚠️ ملاحظات

- `protected` ليس متاحًا مباشرة من الخارج باستخدام `Object`.
- `protected` متاح داخل الـ `Base Class`.
- `protected` متاح داخل الـ `Derived Classes`.
- `private` لا يصل إليه الـ `Derived Class` مباشرة.
- `public` متاح من جميع الجهات المذكورة في الجدول.
- يمكن استخدام `BaseClass::MemberName` للوصول إلى عضو من الـ `Base Class` عندما يسمح مستوى الوصول بذلك.
- المثال يطبّق `protected` مع `Inheritance` من خلال `clsA` و`clsB`.

---

## 💡 الفكرة الأساسية

إذا أردنا أن نعطي الـ `Derived Classes` وصولًا إلى عضو، ولكن لا نريد أن يكون هذا العضو متاحًا للمستخدم الخارجي، نستخدم `protected`.

لذلك:

`private` → للـ `Class` نفسها.

`protected` → للـ `Class` والـ `Derived Classes`.

`public` → من الخارج وداخل الـ `Class` والـ `Derived Classes`.

---

## 🔑 ملخص

- `private` لا يمكن الوصول إليه من الـ `Derived Class`.
- `protected` يمكن الوصول إليه من الـ `Derived Class`.
- `public` يمكن الوصول إليه من الخارج ومن الـ `Derived Class`.
- الـ `Object` من الخارج يرى الأعضاء `public` فقط.
- في `clsB` يمكن الوصول إلى `Var2` و`()Fun2` لأنهما `protected`.
- لا يمكن الوصول إلى `_Var1` و`()_Fun1` لأنهما `private`.
- `clsA::Var2` هي طريقة الوصول إلى `Var2` من خلال اسم الـ `Base Class` داخل المثال.

## 📝 Introduction

We already learned `private`, `protected`, and `public`, but `protected` becomes clearer when we use it with `Inheritance`.

The main idea in this lesson is to know what an `Object` can access from outside and what a `Derived Class` can access from inside.

---

## 🧠 Quick Recap

There are three `Access Specifiers`:

- `private`
- `protected`
- `public`

`private` is available inside the `Class` itself.

`public` is available from outside, inside the `Class`, and from `Derived Classes`.

`protected` is available inside the `Class` and its `Derived Classes`, but it is not directly available from outside.

---

## 🎯 Definition: Protected with Inheritance

> **protected**
>
> A member that is not directly available from outside the `Class`, but is available inside the `Base Class` and its `Derived Classes`.

---

## ⚙️ Difference Between private and protected

Suppose we have:

`private int _Var1`

The `Derived Class` cannot access it directly.

But if we have:

`protected int Var2`

the `Derived Class` can access it from inside the class.

So the important difference is:

`private` → the `Derived Class` cannot directly access it.

`protected` → the `Derived Class` can access it from inside.

Both are not directly available from outside through an `Object`.

---

## 💻 Example: `clsA` and `clsB`

```cpp
#include <iostream>

using namespace std;

class clsA
{
private:
    // only accessible inside this class
    int _Var1;

    void _Fun1()
    {
        cout << "Function 1";
    }

protected:
    // only accessible inside this class and all derived classes
    int Var2;

    void Fun2()
    {
        cout << "Function 1";
    }

public:
    // Accessible inside this class, all derived classes, and outside
    int Var3;

    void Fun3()
    {
        cout << "Function 1";
    }
};

class clsB : public clsA
{
public:

    void Func1()
    {
        cout << clsA::Var2;
    }
};

int main()
{
    system("pause>0");
    return 0;
}
```

`clsA` has three access levels:

- `_Var1` and `_Fun1()` are under `private`.
- `Var2` and `Fun2()` are under `protected`.
- `Var3` and `Fun3()` are under `public`.

---

## 📌 What Does the Object See from Outside?

If we create an `Object` of `clsA` and use `.` to access members, only `public` members can be accessed.

So:

- `Var3` can be accessed.
- `Fun3()` can be accessed.
- `Var2` cannot be accessed.
- `Fun2()` cannot be accessed.
- `_Var1` cannot be accessed.
- `_Fun1()` cannot be accessed.

A member can exist inside a `Class` without being available from outside. The access level controls this.

---

## ⚙️ What Can `clsB` See?

`clsB` inherits from `clsA`:

`class clsB : public clsA`

Inside `clsB`, we can access:

- `Var2` because it is `protected`.
- `Fun2()` because it is `protected`.
- `Var3` because it is `public`.
- `Fun3()` because it is `public`.

But we cannot access:

- `_Var1`
- `_Fun1()`

because they are `private` in `clsA`.

---

## 📌 Accessing `protected` from the Derived Class

Inside `clsB`, we have:

`cout << clsA::Var2;`

Here we use the `Base Class` name with `::` to access `Var2`.

`Var2` is `protected` in `clsA`, so the `Derived Class` can access it.

---

## 📌 Why Not Make Everything public?

Sometimes we want a variable or function to be available to `Derived Classes`, but we do not want outside users to access it through the `Object`.

This is where `protected` is useful.

For example, if we want `clsB` to use:

`Var2`

but we do not want a user of `clsA` to write:

`A1.Var2`

we can define `Var2` as `protected`.

---

## 📌 Important Rule

We can summarize access like this:

| Access Specifier | Inside Class | Outside | Derived Class |
|---|---|---|---|
| `private` | Yes | No | No |
| `protected` | Yes | No | Yes |
| `public` | Yes | Yes | Yes |

---

## 📚 Terminology

| Term | Meaning |
|---|---|
| protected | A member available inside the `Class` and `Derived Classes`, but not from outside |
| private | A member available only inside the `Class` itself |
| public | A member available from outside, inside the `Class`, and from `Derived Classes` |
| Base Class | The class that is inherited from |
| Derived Class | The class that inherits from the `Base Class` |

---

## ⚠️ Notes

- `protected` is not directly available from outside through an `Object`.
- `protected` is available inside the `Base Class`.
- `protected` is available inside `Derived Classes`.
- `private` cannot be accessed directly by a `Derived Class`.
- `public` is available from all the groups shown in the table.
- `BaseClass::MemberName` can be used to access a member of the `Base Class` when the access level allows it.
- The example uses `protected` with `Inheritance` through `clsA` and `clsB`.

---

## 💡 Key Idea

When we want a member to be available to `Derived Classes` but not to outside users, we use `protected`.

So:

`private` → the `Class` itself.

`protected` → the `Class` and `Derived Classes`.

`public` → outside, inside the `Class`, and `Derived Classes`.

---

## 🔑 Summary

- `private` cannot be accessed by the `Derived Class`.
- `protected` can be accessed by the `Derived Class`.
- `public` can be accessed from outside and by the `Derived Class`.
- An `Object` used from outside can access only `public` members.
- In `clsB`, `Var2` and `Fun2()` can be accessed because they are `protected`.
- `_Var1` and `_Fun1()` cannot be accessed because they are `private`.
- `clsA::Var2` is used to access `Var2` through the `Base Class` name in the example.
