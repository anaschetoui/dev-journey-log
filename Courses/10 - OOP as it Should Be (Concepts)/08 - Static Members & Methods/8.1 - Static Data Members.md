# Static Data Members

---

## 📝 مقدمة

عند وجود `Data Member` عادي داخل `Class`، يحصل كل `Object` على نسخة مستقلة منه.

أما عندما نستخدم `static`، فإن العضو يصبح مشتركًا بين جميع الكائنات من نفس الـ `Class`، ويكون على مستوى الـ `Class` بدل أن يكون على مستوى كل `Object`.

---

## 🧠 مراجعة سريعة

المتغيّر العادي داخل الـ `Class` يكون مستقلًا لكل `Object`.

لذلك إذا كان لدينا ثلاثة كائنات، فسيكون لكل واحد منها نسخة خاصة من المتغيّر العادي.

أما `Static Data Member` فليس له نسخة منفصلة لكل كائن، بل توجد نسخة واحدة مشتركة بينهم جميعًا.

---

## 🎯 تعريف: Static Data Member

> **Static Data Member**
>
> متغيّر داخل `Class` يكون مشتركًا بين جميع الـ `Objects` من نفس الـ `Class`.
>
> تكون له نسخة واحدة على مستوى الـ `Class`، وليس نسخة منفصلة لكل `Object`.

---

## ⚙️ كيف يعمل Static Data Member

إذا كان لدينا متغيّر عادي مثل `var`، ثم أنشأنا ثلاثة كائنات:

- `A1`
- `A2`
- `A3`

فسيكون لكل كائن نسخة مستقلة من `var`.

لذلك يمكن أن تكون:

- `A1.var = 10`
- `A2.var = 20`
- `A3.var = 30`

ولا تؤثر قيمة أحدها في الآخر.

أما إذا كان لدينا `static int counter`، فهناك نسخة واحدة فقط من `counter` تشترك فيها جميع الكائنات.

---

## 💻 مثال: `counter`

<div dir="ltr" style="text-align:left;font-family:'Arial',sans-serif;">

```cpp
#include <iostream>
#include <string>
using namespace std;

class clsA
{
public:

    int var;
    static int counter;

    clsA()
    {
        counter++;
    }

    void Print()
    {
        cout << "\nvar     = " << var << endl;
        cout << "counter = " << counter << endl;
    }
};

int clsA::counter = 0; // static variable initialisation outside the class

int main()
{
    clsA A1, A2, A3;

    A1.var = 10;
    A2.var = 20;
    A3.var = 30;

    A1.Print();
    A2.Print();
    A3.Print();

    A1.counter = 500;

    cout << "\nafter chaning the static member counter in one object:\n";

    A1.Print();
    A2.Print();
    A3.Print();
}
```

</div>

في هذا المثال، `var` متغيّر عادي، بينما `counter` هو `Static Data Member`.

عند إنشاء `A1` ثم `A2` ثم `A3`، يتم استدعاء الـ `Constructor` في كل مرة، وفي كل مرة تزيد قيمة `counter` بمقدار واحد.

لذلك تصبح قيمة `counter` تساوي `3` بعد إنشاء الكائنات الثلاثة.

أما `var`، فكل كائن يحتفظ بقيمته الخاصة:

- `A1.var` تساوي `10`.
- `A2.var` تساوي `20`.
- `A3.var` تساوي `30`.

---

## 📌 لماذا نستخدم `static`؟

يمكن استخدام `static` عندما نحتاج إلى بيانات مشتركة بين جميع الكائنات من نفس الـ `Class`.

في المثال، استخدمنا `counter` لمعرفة عدد الـ `Objects` التي تم إنشاؤها من `clsA`.

بدل إنشاء `counter` مستقل لكل كائن، نحتاج إلى قيمة واحدة مشتركة بين الجميع.

---

## ⚙️ تهيئة الـ Static Member

يتم تعريف `static` داخل الـ `Class`:

`static int counter`

لكن تتم تهيئته خارج الـ `Class`:

`int clsA::counter = 0`

في المثال، تم وضع التهيئة خارج `main`.

---

## 📌 مستوى الـ Class وليس مستوى الـ Object

الفرق الأساسي هو أن المتغيّر العادي تابع لكل `Object`، بينما `Static Data Member` تابع للـ `Class`.

لذلك:

- المتغيّر العادي → نسخة لكل `Object`.
- `static` → نسخة واحدة مشتركة بين جميع الـ `Objects`.

ولهذا السبب، عند تغيير `counter` من خلال `A1`:

`A1.counter = 500`

تصبح القيمة `500` عند `A1` و`A2` و`A3` أيضًا.

---

## 📌 تعديل الـ Static Member

يمكن لأي `Object` من نفس الـ `Class` الوصول إلى الـ `Static Data Member` وتعديله.

لكن بما أن العضو مشترك، فإن التعديل لا يبقى خاصًا بالكائن الذي قام به.

في المثال، تعديل:

`A1.counter = 500`

يؤدي إلى أن الكائنات الثلاثة ترى القيمة `500`.

---

## 📚 المصطلحات

| المصطلح | المعنى |
|---|---|
| Static Data Member | متغيّر مشترك بين جميع الـ `Objects` من نفس الـ `Class` |
| Shared | مشترك بين عدة كائنات |
| Initialization | إعطاء قيمة ابتدائية للمتغيّر |
| Lifetime | مدة بقاء المتغيّر موجودًا |

---

## ⚠️ ملاحظات

- `static` يجعل الـ `Data Member` مشتركًا بين جميع الـ `Objects`.
- المتغيّر العادي له نسخة مستقلة لكل `Object`.
- `Static Data Member` يكون على مستوى الـ `Class`.
- في المثال، `counter` له نسخة واحدة فقط.
- يتم تهيئة `counter` خارج الـ `Class`.
- عند إنشاء كل `Object`، يزيد الـ `Constructor` قيمة `counter`.
- تعديل `counter` من خلال كائن واحد يغيّر القيمة التي تراها جميع الكائنات.
- عمر الـ `static` يستمر طوال مدة تشغيل البرنامج، كما تم ربطه بمفهوم `static variable` الذي تم تعلّمه سابقًا.

---

## 💡 الفكرة الأساسية

المتغيّر العادي تابع للكائن، أما `Static Data Member` فهو تابع للـ `Class` ومشترك بين جميع الكائنات.

في المثال، كل كائن يملك `var` الخاصة به، لكن جميع الكائنات تشارك `counter` واحدة.

---

## 🔑 ملخص

- `Static Data Member` هو متغيّر واحد مشترك بين جميع الـ `Objects` من نفس الـ `Class`.
- المتغيّر العادي يكون له نسخة مستقلة لكل `Object`.
- يمكن استخدام `static` عندما نحتاج إلى قيمة مشتركة بين الكائنات.
- `counter` في المثال يستخدم لعدّ عدد الكائنات التي تم إنشاؤها.
- تتم تهيئة `counter` خارج الـ `Class`.
- تعديل `counter` من أي `Object` يغيّر القيمة المشتركة التي تراها جميع الكائنات.

## 📝 Introduction

A normal `Data Member` inside a `Class` has a separate copy for each `Object`.

When we use `static`, the member becomes shared by all objects of the same `Class`. It belongs to the `Class` instead of belonging to each `Object` separately.

---

## 🧠 Quick Recap

A normal variable inside a `Class` is separate for each `Object`.

So, if we have three objects, each object has its own copy of the normal variable.

A `Static Data Member` is different. There is one shared copy for all objects of the same `Class`.

---

## 🎯 Definition: Static Data Member

> **Static Data Member**
>
> A variable inside a `Class` that is shared by all `Objects` of the same `Class`.
>
> It has one shared copy at the `Class` level instead of a separate copy for each `Object`.

---

## ⚙️ How a Static Data Member Works

Suppose we have a normal variable such as `var`, and we create three objects:

- `A1`
- `A2`
- `A3`

Each object has its own copy of `var`.

So we can have:

- `A1.var = 10`
- `A2.var = 20`
- `A3.var = 30`

Changing one does not change the others.

A `static int counter` is different. There is one `counter` shared by all the objects.

---

## 💻 Example: `counter`

```cpp
#include <iostream>
#include <string>
using namespace std;

class clsA
{
public:

    int var;
    static int counter;

    clsA()
    {
        counter++;
    }

    void Print()
    {
        cout << "\nvar     = " << var << endl;
        cout << "counter = " << counter << endl;
    }
};

int clsA::counter = 0; // static variable initialisation outside the class

int main()
{
    clsA A1, A2, A3;

    A1.var = 10;
    A2.var = 20;
    A3.var = 30;

    A1.Print();
    A2.Print();
    A3.Print();

    A1.counter = 500;

    cout << "\nafter chaning the static member counter in one object:\n";

    A1.Print();
    A2.Print();
    A3.Print();
}
```

In this example, `var` is a normal variable, while `counter` is a `Static Data Member`.

When `A1`, `A2`, and `A3` are created, the `Constructor` is called each time, and `counter` increases by one.

So, after creating the three objects, `counter` becomes `3`.

`var` is different because each object has its own value:

- `A1.var` is `10`.
- `A2.var` is `20`.
- `A3.var` is `30`.

---

## 📌 Why Use `static`?

We can use `static` when we need data that is shared by all objects of the same `Class`.

In the example, `counter` is used to count how many `Objects` were created from `clsA`.

Instead of having one `counter` for every object, we need one shared value.

---

## ⚙️ Initializing the Static Member

We declare the `static` member inside the `Class`:

`static int counter;`

But we initialize it outside the `Class`:

`int clsA::counter = 0;`

In the example, the initialization is placed outside `main`.

---

## 📌 Class Level, Not Object Level

The main difference is that a normal variable belongs to each `Object`, while a `Static Data Member` belongs to the `Class`.

So:

- Normal variable → one copy for each `Object`.
- `static` → one shared copy for all `Objects`.

For this reason, when we change `counter` through `A1`:

`A1.counter = 500;`

the value becomes `500` for `A1`, `A2`, and `A3` too.

---

## 📌 Changing the Static Member

Any `Object` of the same `Class` can access and change the `Static Data Member`.

But because the member is shared, the change is not private to the object that made it.

In the example:

`A1.counter = 500;`

makes all three objects see the value `500`.

---

## 📚 Terminology

| Term | Meaning |
|---|---|
| Static Data Member | A variable shared by all `Objects` of the same `Class` |
| Shared | Used by more than one object |
| Initialization | Giving an initial value to a variable |
| Lifetime | The time a variable stays alive |

---

## ⚠️ Notes

- `static` makes the `Data Member` shared by all `Objects`.
- A normal variable has a separate copy for each `Object`.
- A `Static Data Member` is at the `Class` level.
- In the example, there is only one `counter`.
- `counter` is initialized outside the `Class`.
- Each time an `Object` is created, the `Constructor` increases `counter`.
- Changing `counter` through one object changes the value seen by all objects.
- The lifetime of the `static` variable continues for the life of the program, as connected to the `static variable` idea studied before.

---

## 💡 Key Idea

A normal variable belongs to the object, while a `Static Data Member` belongs to the `Class` and is shared by all objects.

In the example, every object has its own `var`, but all objects share one `counter`.

---

## 🔑 Summary

- A `Static Data Member` is one shared variable for all `Objects` of the same `Class`.
- A normal variable has a separate copy for each `Object`.
- We use `static` when we need a shared value between objects.
- `counter` in the example counts how many objects were created.
- `counter` is initialized outside the `Class`.
- Changing `counter` through any `Object` changes the shared value seen by all objects.
