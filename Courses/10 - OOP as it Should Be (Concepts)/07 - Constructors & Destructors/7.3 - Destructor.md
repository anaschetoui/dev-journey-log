# Destructor

---

## 📝 مقدمة

الـ `Destructor` مرتبط بنهاية حياة الـ `Object`.

بعد إنشاء الكائن واستخدامه، يصل وقت يتم فيه تدميره وإزالة البيانات الخاصة به من الذاكرة. عند حدوث ذلك، يتم استدعاء الـ `Destructor`.

---

## 🧠 مراجعة سريعة

الـ `Constructor` يتم استدعاؤه عند إنشاء الـ `Object`.

الـ `Destructor` يعمل في الاتجاه المعاكس، ويتم استدعاؤه عند تدمير الـ `Object`.

---

## 🎯 تعريف: Destructor

> **Destructor**
>
> دالة عضو يتم استدعاؤها عند تدمير الـ `Object`.
>
> تحمل نفس اسم الـ `Class`، لكن يسبق الاسم الرمز `~`.

---

## ⚙️ كيف يعمل Destructor

عند إنشاء `Object` من `Class`، يتم استدعاء الـ `Constructor`.

عندما ينتهي عمر الـ `Object` ويتم تدميره، يتم استدعاء الـ `Destructor` باعتباره آخر دالة عضو يتم استدعاؤها لهذا الكائن.

يمكن وضع الكود الذي نريد تنفيذه قبل انتهاء حياة الكائن داخل الـ `Destructor`.

---

## 💻 مثال: Destructor في `clsPerson`

<div dir="ltr" style="text-align:left;font-family:'Arial',sans-serif;">

```cpp
class clsPerson
{
public:

    clsPerson()
    {
        cout << "Hi I am Constructor";
    }

    ~clsPerson()
    {
        cout << "Hi I am Destructor";
    }
};
```

</div>

في المثال، اسم الـ `Destructor` هو `clsPerson~`.

عند إنشاء `Object` من `clsPerson`، يتم استدعاء الـ `Constructor`.

وعند تدمير الكائن، يتم استدعاء الـ `Destructor`.

---

## 📌 متى يتم استدعاء Destructor؟

إذا تم إنشاء `Object` عادي داخل دالة، ثم انتهت هذه الدالة، يتم تدمير الكائن عند خروجه من نطاق الدالة.

أما الـ `Object` الموجود داخل `main`، فيبقى موجودًا حتى ينتهي نطاق `main`.

لذلك، في المثال الذي يعتمد على `main`، لا يظهر استدعاء الـ `Destructor` قبل انتهاء هذا النطاق.

---

## 📌 Constructor و Destructor

| Constructor | Destructor |
|---|---|
| عند إنشاء الـ `Object` | عند تدمير الـ `Object` |
| في بداية حياة الكائن | في نهاية حياة الكائن |
| يحمل اسم الـ `Class` | يحمل اسم الـ `Class` مع `~` |
| يمكن أن يستقبل parameters | لا يستقبل parameters |
| يتم استدعاؤه عند الإنشاء | يتم استدعاؤه عند التدمير |

---

## ⚠️ قواعد Destructor

- يوجد `Destructor` واحد فقط داخل الـ `Class`.
- لا يمكن عمل `Overloading` له.
- لا يستقبل parameters.
- لا يملك نوع إرجاع.
- يتم استدعاؤه عند تدمير الـ `Object`.
- هو آخر `Member Function` يتم استدعاؤها للكائن.

---

## 📌 استخدام Destructor

يمكن وضع عمليات يجب تنفيذها قبل انتهاء حياة الـ `Object` داخل الـ `Destructor`.

من الأمثلة المذكورة:

- حفظ بيانات في `File`.
- حفظ بيانات في `Database`.
- إغلاق `Connection`.
- تنظيف موارد مرتبطة بالكائن.

---

## ⚙️ Destructor والذاكرة الديناميكية

عند إنشاء كائن باستخدام `new`، يتم وضعه في الذاكرة الديناميكية.

يجب تحرير هذه الذاكرة بشكل صحيح. القاعدة المذكورة هي:

`new` يتبعها `delete`

أما الـ `Destructor` فيمكن استخدامه لتنظيف الموارد المرتبطة بالكائن قبل انتهاء عمره.

---

## 📌 عمر الـ Object

يمكن التفكير في حياة الـ `Object` بهذه المراحل:

1. إنشاء الـ `Object` → `Constructor`.
2. استخدام الـ `Object`.
3. تدمير الـ `Object` → `Destructor`.

---

## 📚 المصطلحات

| المصطلح | المعنى |
|---|---|
| Destructor | دالة عضو يتم استدعاؤها عند تدمير الـ `Object` |
| `~` | الرمز المستخدم قبل اسم الـ `Class` لتعريف الـ `Destructor` |
| Object Lifetime | مدة بقاء الـ `Object` موجودًا |
| Dynamic Memory | ذاكرة يتم حجزها أثناء تشغيل البرنامج |
| `new` | إنشاء كائن في الذاكرة الديناميكية |
| `delete` | تحرير الذاكرة الديناميكية |
| Cleanup | تنظيف الموارد قبل انتهاء حياة الكائن |

---

## 💡 الفكرة الأساسية

الـ `Destructor` هو آخر جزء من دورة حياة الـ `Object`.

يتم تشغيله عند تدمير الكائن، ويمكن وضع عمليات التنظيف أو إغلاق الموارد داخله.

---

## 🔑 ملخص

- `Destructor` يتم استدعاؤه عند تدمير الـ `Object`.
- يحمل نفس اسم الـ `Class` مع `~`.
- هو آخر `Member Function` يتم استدعاؤها للكائن.
- لا يستقبل parameters ولا يمكن عمل `Overloading` له.
- يمكن استخدامه للتنظيف وإغلاق الموارد.
- عند استخدام `new`، يجب تحرير الذاكرة الديناميكية باستخدام `delete`.
- الكائنات العادية تُدمّر عند انتهاء نطاقها.

## 📝 Introduction

A `Destructor` is related to the end of an `Object`'s lifetime.

After the object is created and used, it reaches a point where it is destroyed and its data is removed from memory. When this happens, the `Destructor` is called.

---

## 🧠 Quick Recap

A `Constructor` is called when an `Object` is created.

A `Destructor` works in the opposite direction and is called when the `Object` is destroyed.

---

## 🎯 Definition: Destructor

> **Destructor**
>
> A member function that is called when an `Object` is destroyed.
>
> It has the same name as the `Class`, but the name starts with `~`.

---

## ⚙️ How a Destructor Works

When an `Object` is created from a `Class`, the `Constructor` is called.

When the object's lifetime ends and the object is destroyed, the `Destructor` is called as the last member function for that object.

We can put code that must run before the object's lifetime ends inside the `Destructor`.

---

## 💻 Example: Destructor in `clsPerson`

```cpp
class clsPerson
{
public:

    clsPerson()
    {
        cout << "Hi I am Constructor";
    }

    ~clsPerson()
    {
        cout << "Hi I am Destructor";
    }
};
```

In the example, the `Destructor` is called `~clsPerson`.

When an `Object` of `clsPerson` is created, the `Constructor` is called.

When the object is destroyed, the `Destructor` is called.

---

## 📌 When Is the Destructor Called?

If a normal `Object` is created inside a function and the function ends, the object is destroyed when it leaves the function scope.

An `Object` inside `main` stays alive until the `main` scope ends.

So, in the example using `main`, we do not see its `Destructor` before that scope ends.

---

## 📌 Constructor and Destructor

| Constructor | Destructor |
|---|---|
| When the `Object` is created | When the `Object` is destroyed |
| At the start of the object's lifetime | At the end of the object's lifetime |
| Has the `Class` name | Has the `Class` name with `~` |
| Can receive parameters | Does not receive parameters |
| Called during creation | Called during destruction |

---

## ⚠️ Destructor Rules

- There is only one `Destructor` in a `Class`.
- It cannot be overloaded.
- It does not receive parameters.
- It has no return type.
- It is called when the `Object` is destroyed.
- It is the last `Member Function` called for the object.

---

## 📌 Using a Destructor

We can put operations that must happen before the `Object` ends its lifetime inside the `Destructor`.

Examples mentioned in the lesson include:

- Saving data to a `File`.
- Saving data to a `Database`.
- Closing a `Connection`.
- Cleaning resources related to the object.

---

## ⚙️ Destructor and Dynamic Memory

When an object is created with `new`, it is placed in dynamic memory.

This memory must be released correctly. The rule mentioned in the lesson is:

`new` should be followed by `delete`

A `Destructor` can also be used to clean resources related to the object before its lifetime ends.

---

## 📌 Object Lifetime

We can think about the lifetime of an `Object` in these stages:

1. Create the `Object` → `Constructor`.
2. Use the `Object`.
3. Destroy the `Object` → `Destructor`.

---

## 📚 Terminology

| Term | Meaning |
|---|---|
| Destructor | A member function called when an `Object` is destroyed |
| `~` | The symbol used before the `Class` name to define a `Destructor` |
| Object Lifetime | The time an `Object` stays alive |
| Dynamic Memory | Memory allocated while the program is running |
| `new` | Creates an object in dynamic memory |
| `delete` | Releases dynamic memory |
| Cleanup | Cleaning resources before the object's lifetime ends |

---

## 💡 Key Idea

A `Destructor` is the final part of an `Object`'s lifetime.

It runs when the object is destroyed, and it can contain cleanup work or code to close resources.

---

## 🔑 Summary

- A `Destructor` is called when an `Object` is destroyed.
- It has the same name as the `Class` with `~` before it.
- It is the last `Member Function` called for the object.
- It receives no parameters and cannot be overloaded.
- It can be used for cleanup and closing resources.
- When using `new`, dynamic memory must be released with `delete`.
- Normal objects are destroyed when they leave their scope.
